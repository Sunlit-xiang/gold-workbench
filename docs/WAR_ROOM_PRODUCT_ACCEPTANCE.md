# Macro War Room — 产品验收记录

2026-10-06，本机 `http://127.0.0.1:3015/war-room.html` 已实际打开，不以测试数量替代使用体验。

## 本轮交付边界

新增 Situation Room 首屏、Morning Brief、独立专业研究员桌面、协作时间线、私人追问及明确 DEMO。主界面从原始数据前置调整为可读背景/判断前置。DEMO 是浏览器纯合成数据，所有报告和数值均显著标识，不能提交研究或冻结接口；演示追问只返回固定交互说明。

| 场景问题 | 实际检查结果 |
| --- | --- |
| 三十秒知道三件重要的事？ | DEMO 首屏可以读出三个主题及主管摘要；真实模式没有 AI 晨会，因此显示 NOT YET ANALYZED，不虚构今日要闻。真实市场场景尚未达到完整验收。 |
| 知道最大分歧？ | DEMO 首屏直接显示流动性改善与通胀风险的冲突；真实模式说明没有完成团队讨论。 |
| 点击研究员查看完整证据？ | 实际打开通胀/利率研究桌，显示问题、解释、支持/反对、与流动性研究员的分歧、已读资料及可展开源值/时间/变换。来源点击可继续展开。 |
| 继续追问？ | DEMO 实际输入问题，返回显著固定 UI 说明，不冒充研究员回答。真实私人会话持久化/API 已测试；有效 Provider 实调用尚未验收。 |
| 区分事实、推论、团队观点？ | 首页背景标记程序生成；晨会段落按事实/机制/分歧/判断/观察区分；Confidence 明确为自评、非命中率。模板格式不能证明语义真实，仍需真实研究质量评价。 |
| 知道数据不足在哪里？ | 真实模式明确没有今日摘要、没有团队分歧记录、缺少 OIS/发布前预期；原始证据保持原观察窗口，未标成今日消息。 |

## 工程支持而非产品效果证明

- 最终本机与发布工作副本：318 个 Python 测试、14 个 Node 测试通过。GitHub 首次构建恢复旧归档遇到 HTTP 500，原任务重试成功；随后进度展示增量构建 [37460882391](https://github.com/Sunlit-xiang/gold-workbench/actions/runs/37460882391) 成功，部署代码 `742a402561d399dd16652f3fb0117d452b9d8500`。
- 已实际读取公开首页 DOM，确认 Situation Room、NOT YET ANALYZED、团队和证据结构；公开 JSON/JS HTTP 读回正常，实际受理进度代码已发布，公开 Gold 冻结记录仍六十条。远端交互自动化随后超时，因此线上 DEMO/追问不记为完整交互通过；本机上述交互验收已完成。
- 新增运行中展示只来自 daily session 的真实 request/turn 记录；pending 表示请求已受理未返回，不等于模型一定仍在工作。私密问题不进入公开进度。团队研究发起后页面周期读取这些记录，没有虚构的进度动画。

- 原 Gold 批准计算 hash 未改变；本机冻结预测仍二十条。本轮没有调用冻结/重训；云端已存在的历史由原归档保护流程恢复。
- WR-P2 模拟 Provider 验证完整派题、成员阅读、Skeptic 读取同行、主管审阅、真实定向补证、追加最终报告；原报告 ID 和内容保留。
- 未配置凭据时不执行模型调用、不保存虚假成功研究。私密问答不进入静态公开报告。
- 外部先验核对见 [Prior-Art Review](WAR_ROOM_PRIOR_ART_REVIEW.md)；上游持续跟踪见 [Architecture Watch](AGENT_ARCHITECTURE_WATCH.md)。

## 下一验收门槛

需要有效 Provider 在真实资料上完成一次晨会和两轮追问：逐项审查事实引用、报告间真正的分歧、补证是否增加信息、是否承认未解决问题，并以实际读者阅读体验评价。没有达到这一步，不宣称正式金融研究产品全部完成或具备 Edge。原 DSH 可选适配与公共认证交互后端都不是本轮已交付能力。
